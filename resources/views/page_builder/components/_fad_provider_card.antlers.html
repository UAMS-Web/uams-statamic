Rendered once per provider inside the Providers block's collection loop (UAMS-Web/uams-statamic-archive#64). Editor- and taxonomy-controlled text is escaped with `sanitize` because Antlers output is raw by default. Pass `fad_facet="true"` (the Providers block sets it when reader filtering is enabled, UAMS-Web/uams-statamic-archive#1242) to emit the card's facet anchor: `data-fad-card` plus space-delimited term/entry slugs in `data-expertise` / `data-specialty` / `data-region`, the contract the `fadFilter` Alpine engine reads. The slugs come from the provider's `expertise` (entries → `clinical_expertise`), `clinical_specializations` (terms), and computed `regions` (terms, aggregated from the provider's locations). Unlike the free-text values below, these need no `sanitize`: Statamic slugs are URL-safe (`[a-z0-9-]`), so they cannot carry HTML special characters or break out of the attribute. Pass `profile_url="…"` to point the "View Profile" CTA somewhere other than the provider's own permalink — the `/providers` directory passes the clinical lens URL (`/provider/{slug}`, UAMS-Web/uams-statamic-archive#571) so a card leads to the clinical profile rather than the base people page. Falls back to `{{ url }}` when absent or empty, which is what the Find-a-Doc Providers block (UAMS-Web/uams-statamic-archive#64) still relies on. Pass `fad_directory="true"` as well (the UAMS-Web/uams-statamic-archive#570 `/providers` directory sets both) to emit the wider WP-parity facet set the `fadProviderDirectory` engine reads: `data-conditions` / `data-treatments` / `data-patient_types` / `data-location` (entry/taxonomy slugs — URL-safe like the three above), `data-gender` / `data-primary_care` (controlled `radio`/`toggle` values), and `data-language` (the BCP-47 codes — the `language` select augments to `{value,label}` rows, so we `pluck:'value'` the codes; a bare `join` over the rows would emit `Array`).
