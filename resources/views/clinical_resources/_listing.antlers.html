'' }} {{# Optional provider filter from the query string (?provider={slug}), applied via the `clinical_resources_for_provider` scope (UAMS-Web/uams-statamic-archive#1692). The relation runs the other way — `clinical_resources` is a field on `people` — so the scope resolves the person and constrains to the ids they relate, which no inline `where` can do. An absent, blank, UNKNOWN, unpublished, or private slug leaves the archive unfiltered, matching how `clinical_resource_type` treats an absent type. `$filter_provider_name` is therefore the reliable test for "a provider filter is actually in force": it is resolved by the same lookup the scope does, so a typo'd slug shows no notice rather than claiming to be filtered to a provider who does not exist. `$filter_provider_active` — NOT the raw parameter — is what the type tabs carry. Propagating an unresolvable slug would contradict this template's own test for a live filter: the archive would correctly show everything and no notice, while every tab still advertised `?provider=nobody`. Antlers coerces a bare `?provider` (no value) to a bool, so the raw parameter is also not a safe string to concatenate — a `true` renders as `1` and points every tab at a provider nobody has. #}} {{ $filter_provider_name = {clinical_resource_filter:provider_name provider="{{ get:provider }}"} }} {{ $filter_provider_active = $filter_provider_name ?
