{{# @name Account: Reset password @desc The page the emailed reset link lands on. Route-rendered, NOT a `pages` entry (#2113). #}} {{# WHY THIS ONE IS NOT AN ENTRY, when the other four are. The other four auth pages had no display route at all, so a `pages` entry with a `template:` override supplies one. This URL is different: Statamic already registers `GET !/auth/password/reset/{token}` as `statamic.password.reset`, handled by ResetPasswordController@showResetForm — which renders Control Panel Inertia UI, with a "back to login" pointing at `cp_route('login')`. An Antlers template cannot intercept it, because the request never reaches the entry resolver; the registered controller answers first. So a public visitor would request a reset, follow the email, and arrive in an admin interface. routes/web.php overrides that one handler to render this view instead. The decision is recorded on #2113 (2026-09-08) and is deliberately narrower than the rejected "explicit routes for the five pages": this is a single handler for a URL Statamic already owns and no editor would ever set. There is no entry behind this view, so it takes `title_options` implicitly — the page-header renders nothing and the

below is the page's only heading, matching how the error pages do it. #}} {{ partial:layout/article }} {{ partial:layout/entry-content content_width="true" }}
