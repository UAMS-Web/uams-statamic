{{# @name Clinical Resources Listing @desc Type-filterable, paginated card grid of the site's clinical resources. (UAMS-Web/uams-statamic-archive#576) UAMS-Web/uams-statamic#1583: a GET form narrows the grid by a text search (`?q=`), a location (`?location=`) and an area of expertise (`?expertise=`), each facet a slug, and orders it by `?sort=`, so every filtered view is a link. The filters run through the `clinical_resources_archive_filter` scope, which treats a blank parameter as no filter, as the `clinical_locations` archive's filter does. They combine with the type tabs and the provider filter, which the form carries as hidden fields and the tabs carry in their links. The result count is the paginator's total, the selected values are listed above the results, and Reset returns to the unfiltered archive. Every value reflected from the query string is escaped (Antlers output is raw by default). Condition and treatment facets are not built: those pages no longer route on this site. #}} {{# Optional type filter from the query string (?type=article|audio|…). Applied via the `clinical_resource_type` query scope, NOT the collection tag's inline `blueprint:is`: an empty `blueprint:is` matches no entry in Statamic 6, so an unfiltered ("All") request would render empty. The scope leaves the query unfiltered when no type is given and constrains to the blueprint otherwise. `$filter_type` is kept only for the control's active state + the empty message. #}} {{ $filter_type = get:type ?? '' }} {{# Optional provider filter from the query string (?provider={slug}), applied via the `clinical_resources_for_provider` scope (UAMS-Web/uams-statamic-archive#1692). The relation runs the other way — `clinical_resources` is a field on `people` — so the scope resolves the person and constrains to the ids they relate, which no inline `where` can do. An absent, blank, UNKNOWN, unpublished, or private slug leaves the archive unfiltered, matching how `clinical_resource_type` treats an absent type. `$filter_provider_name` is therefore the reliable test for "a provider filter is actually in force": it is resolved by the same lookup the scope does, so a typo'd slug shows no notice rather than claiming to be filtered to a provider who does not exist. `$filter_provider_active` — NOT the raw parameter — is what the type tabs carry. Propagating an unresolvable slug would contradict this template's own test for a live filter: the archive would correctly show everything and no notice, while every tab still advertised `?provider=nobody`. Antlers coerces a bare `?provider` (no value) to a bool, so the raw parameter is also not a safe string to concatenate — a `true` renders as `1` and points every tab at a provider nobody has. #}} {{ $filter_provider_name = {clinical_resource_filter:provider_name provider="{{ get:provider }}"} }} {{ $filter_provider_active = $filter_provider_name ? '' }} {{ $filter_location = get:location ?? '' }} {{ $filter_expertise = get:expertise ??
