# Specification: UAMS Health Talk podcast source and rendition model

This document records where **UAMS Health Talk** episodes actually live, what the source can and cannot supply, and how episodes map onto the Statamic `audio` content model. It exists because the episodes were **never WordPress content**, so nothing about them is recoverable from a WXR export and none of it is a `wordpress-importer` concern.

> **Scope.** This is a source and mapping record, not an implementation. No episode ingestion exists in the app today; the material below is the pinned target for whenever one is built. All figures were verified against the live source on **2026-07-31** and are dated because the catalog grows by roughly one episode a month.

## Where the episodes live

UAMS Health Talk is produced and hosted by **DoctorPodcasting** (RadioMD, LLC d/b/a DoctorPodcasting), under client code `uams`. On the WordPress site, `uamshealth.com/podcast/` renders a third-party widget `<iframe>` — the episodes are not stored, indexed, or served by WordPress at any point.

That explains the negative findings recorded in `UAMS-Web/wordpress-importer#424`: across all 259 WXR exports there is no podcast post type and no episode metadata. WordPress holds exactly three podcast-adjacent artifacts, none of them content:

- the `/podcast` page carrying the widget embed;
- `podcast_guest_name_uams_health_talk` on provider records — a vendor widget filter string, not a relationship, retired by #1685;
- seven incidental title mentions in unrelated posts.

Two public, unauthenticated endpoints carry everything:

| Source | URL | Verified |
| --- | --- | --- |
| RSS feed | `https://support.doctorpodcasting.com/podcastfeed/287` | 200, 251,958 bytes, 114 items |
| Per-episode page | `https://support.doctorpodcasting.com/client/uams/item/<customid>` | 200 on all 114 |

The per-episode page is the same endpoint the public site's widget loads, which is why it needs no credentials. The vendor's **client portal** (`client.doctorpodcasting.com`) is credentialed and is **not** a data dependency — it was read once to establish the publication-status facts recorded below, and that knowledge now lives in this document.

## The feed

Channel: `UAMS Health Talk`, `<language>en-US`, `<itunes:type>episodic`, `<itunes:category text="Health &amp; Fitness">`, generated by `FeedCreator 1.8.3 (joomRSS 1.1.8)`. Episodes span **2019-07-22 → 2026-07-14**.

The complete per-item element vocabulary:

`title` · `link` · `guid` · `customid` · `k2_itemid` · `pubDate` · `itunes:author` · `description` · `itunes:summary` · `category` · `itunes:keywords` · `itunes:duration` · `podcast:transcript` · `enclosure`

Notes that matter to a consumer:

- **`customid` and `k2_itemid` are the same value** (e.g. `69184`) — the vendor's Joomla/K2 item id. This is the only stable primary key, and it joins the feed to the item page, the player embed, and the site's `?segitem=` deep links.
- **`guid`** is `http://radiomd.com/uams/item/<id>-<slug>` with `isPermaLink="false"` — an identifier, not a resolvable URL.
- **`link`** is the live WordPress page, which makes existing site links to episodes resolvable against the feed.
- **`description` and `itunes:summary` are byte-identical**, both HTML: a leading `<a><img>` thumbnail anchor followed by the show-notes paragraphs. A consumer must strip the leading anchor to obtain clean show notes.
- **`category` carries the client name**, not a topic — a tenancy marker in a multi-client system, useless as taxonomy. Topics live in `itunes:keywords` (e.g. `Audiology, Hearing-Loss, Hearing-Aid-Services`), hyphenated when multi-word.
- **`enclosure`** is always `type="audio/mpeg"`, pointing at `…/download/<customid>/arkansas_medical_sciences/uams<N>.mp3`.

**Absent, and deliberately noted:** `itunes:episode`, `itunes:season`, `itunes:episodeType`, per-item `itunes:image`, `podcast:medium`, `podcast:person`, `podcast:alternateEnclosure`, and `content:encoded` — the `content` namespace is declared on the root element and never used. There is **no reference to YouTube anywhere in the feed** (zero occurrences of `youtube`, `youtu.be`, `ytimg`, or `/watch?v=`).

### Transcripts in the feed

Ten episodes — `109`–`118`, everything published since **2026-01-05** — carry **three** `podcast:transcript` elements each, correctly typed:

```xml
<podcast:transcript url=".../uams118_captions.vtt"          type="text/vtt"         language="en-US" rel="captions" />
<podcast:transcript url=".../uams118_transcription.txt"     type="text/plain"       language="en-US" />
<podcast:transcript url=".../uams118_transcription.json"    type="application/json" language="en-US" />
```

This is a platform feature with a clean start date, not a partial backfill — spot-checks of the caption URL for eps `108`, `107`, `105`, `100`, `090`, `075`, `060`, `050`, `030`, `016`, and `001` all return 404.

## The public item pages

Each `client/uams/item/<customid>` page carries, for **all 114** episodes:

- **`Featured Speaker(s)`** — 105 distinct people, with a full biography paragraph. Six episodes are panels, using the plural label with `|`-delimited names in an `<h6>` (e.g. `Lexie Vaughn, MD | Tyler Rives, M.D`). Name strings are dirty; note the missing trailing period.
- **A rendered `Transcription:`** section — full text with `(Host)` / `(Guest)` speaker labels, median ~10,900 characters (min 4,848, max 22,844). Present on **111 of 114**; eps `037` and `038` have none and ep `004` has a 237-character stub.
- **A `uamshealth.com/provider/<slug>/` link on 45 of 114** episodes (40 distinct providers), which is a slug-level join key into the migrated `people` collection — no fuzzy name matching required. See *Resolving credits to `people`* below for the other 69.

Host identity is unreliable in the transcript speaker labels — ep `118` gives "Amanda Wilde", ep `115` only "Maggie" — which is one reason the `podcast:person` vendor ask below matters.

## Field mapping onto the `audio` blueprint

Target fields are the episode group on [`posts/audio.yaml`](../../resources/blueprints/collections/posts/audio.yaml) and [`clinical_resources/audio.yaml`](../../resources/blueprints/collections/clinical_resources/audio.yaml), gated on the `series` term's `subtype` containing `podcast` (UAMS-Web/uams-statamic-archive#1611).

| Field | Source | Coverage |
| --- | --- | --- |
| `show_notes` | feed `<description>`, leading `<a><img>` stripped | 114/114 |
| `episode_duration` | feed `<itunes:duration>` (`HH:MM:SS`) | 114/114 |
| `episode_number` | **derived** from `<enclosure url>` → `uams118.mp3` | 113/114 |
| `podcast_credits` | item page `Featured Speaker(s)`, `href` → `people` | 114/114 |
| `episode_transcript` | item page `Transcription:` | 111/114 |
| `season_number` | — | **unmappable** |

- **`season_number` is unmappable, not missing.** The channel is `episodic`, no item carries `<itunes:season>`, and numbering is flat 001–118. It should be left empty by design, not tracked as a gap.
- **`episode_number` has no field in the source.** It is parsed from the enclosure filename. One item yields nothing: `uams016bpd.mp3` (item `41530`, "Meet Dr. Joseph Henske"), a Physician BioPod variant.
- Durations range 81 s – 1,298 s, mean 706 s.

### Resolving credits to `people`

`podcast_credits` resolves through `uamsweb_post_creator_roles_audio` to `creator_person`, an **entries relationship into `people`** — not free text. A guest who cannot be resolved to an entry therefore cannot be stored at all, and the episode ingests with empty credits.

Coverage splits three ways:

| Group | Episodes | Resolution |
| --- | --- | --- |
| Carries a `provider/<slug>/` link | 45 | Slug join — reliable |
| No link, speaker is a physician | part of 69 | No plan; profile almost certainly exists |
| No link, speaker is non-physician staff | part of 69 | No plan; a `people` entry may never exist |

The 69 link-less episodes carry **66 distinct speakers**, a mix of physicians whose item page simply omitted the profile link (`Patrick W. Jennings, M.D.`, `Ashley Booth Norse, M.D.`) and non-physician staff (`Isis Pettway, LPC`, `Alyssa Frisby, MS, RD, LD`, `Jonathan Clarke, Licensed Certified Social Worker`) who may have no entry to point at.

The slug format is confirmed compatible: checked against a 43-entry partial test-import set, `c-lowry-barnes` and `t-glenn-pait` match exactly. The remaining 38 provider slugs have no local match only because the collection is not yet populated.

**This is an open decision, not a solved mapping** — tracked on UAMS-Web/uams-statamic-archive#1803. The candidate resolutions are the vendor's `podcast:person href` (which would supply the URL for every episode and dissolve the problem), an editorial backfill of the 66 names, name matching against `people` (risky — the source's name strings are dirty), or accepting empty credits on those episodes. Whichever is chosen bounds how complete #1685's provider-lens list can be.

## Published set versus production catalog

The vendor portal lists **116** episodes; the feed publishes **114**. The difference is deliberate, and the numbering across 1–118 accounts fully:

| Episode numbers | Status | In feed |
| --- | --- | --- |
| 113 episodes | Published | yes |
| `018`, `058`, `062` | Unpublished — featured provider no longer at UAMS | no, correctly |
| `075` | Canceled — never produced | no |
| `017` | No record in any source | no |
| `uams016bpd` | Physician BioPod variant | yes (the 114th item) |

**Ingest from the feed, never from the portal inventory.** The portal's Content Library reports *file* status — all three withdrawn episodes read `Created and Sent` there, indistinguishable from a live episode. Only the portal's Promotion view reports publication status. An inventory built from the Content Library would republish three episodes UAMS deliberately withdrew because the clinician departed.

Because withdrawal is expressed only by an episode disappearing from the feed, with no tombstone and no notification, **the ingestion must reconcile on a schedule** and unpublish entries whose id has left the feed. The live WordPress site inherits this behavior for free by rendering a vendor iframe; first-party entries do not.

## Renditions: audio and video

Ten episodes have a video ("vodcast") rendition in addition to audio: `083`, `109`–`113`, `115`–`118`. Ep `114` is audio-only.

- **The renditions are different edits**, not the same file — the video runs longer in every observed pair (ep `115`: 12:11 vs 11:41; ep `113`: 14:01 vs 13:10; ep `112`: 10:03 vs 9:36).
- **Masters are production files, not web encodes** — `clientfiles.doctorpodcasting.com/arkansas_medical_sciences/uams<N>_vodcast.mp4`, 678 MB – 1.87 GB each, ~10.5 GB total. Ep `115` is 1,424,189,819 bytes for 12:11, roughly 15.6 Mbps.
- **The feed does not express video at all** — every enclosure is `audio/mpeg`, and there are zero `.mp4` references.

### Both renditions are on YouTube, and they are distinguishable

Both live on `@UAMSHealth`, and the rows can be told apart:

| | RSS-ingested audio | Uploaded video |
| --- | --- | --- |
| Thumbnail | `healthtalk` logo | real video frame |
| Description | opens with a bare `…/media/k2/items/cache/…` URL | human-written prose |
| Studio status | `Released` | `Published` |
| Duration | matches `itunes:duration` exactly | never matches |

The audio rows arrive via YouTube's RSS podcast ingestion, which can only publish what the feed declares — hence thumbnail-over-audio. The video rows are separate uploads. As of 2026-07-31 video was published through ep `115`; `116`–`118` had masters but no upload.

**The only machine-derivable episode→YouTube link runs the wrong way:** the ingested audio rows carry the feed description verbatim, including a per-episode `…/cache/<hash>_S.jpg` URL that maps back to a feed item. The uploaded video rows have human descriptions with no such marker. If automation is ever needed, the reliable discriminator is duration — the audio row matches `itunes:duration` to the second, the video row never does.

### Why the vendor's video files are not directly embeddable

The app could render them — [`sets/_box.antlers.html`](../../resources/views/sets/_box.antlers.html) delegates to [`sets/_video.antlers.html`](../../resources/views/sets/_video.antlers.html), whose native HTML5 `<video>` path is gated only on a hardcoded `app.box.com` host check plus the `box_mime` modifier and the `box_shared_static_video_url` rule. Four things block it:

1. **Vendor agreement.** Presenting the assets outside DoctorPodcasting's own embeds requires a contract review, and linking directly to their bucket bills egress to them at ~1.4 GB per view.
2. **File size.** A progressive `<video>` has no rendition ladder; a phone pulls the full ~15.6 Mbps master.
3. **Caption drift.** The VTT is timed to the *audio* edit — ep `115`'s last cue starts at 11:32 against 11:41 audio and 12:11 video — so attaching it to the video drifts, failing WCAG 1.2.2.
4. **No CORS.** Neither `files.doctorpodcasting.com` nor `clientfiles.doctorpodcasting.com` sends `access-control-allow-origin`. An external `<track>` cannot load, and marking the player `crossorigin` to try would make the browser CORS-check and block the video too.

YouTube is therefore the presumptive player: already transcoded, already captioned, no bandwidth or contractual exposure.

## The vendor ask

Keeping each episode a **single `<item>`** with video as an alternate rendition is the smallest change for the vendor and preserves a 1:1 episode→entry mapping. The `<podcast:alternateEnclosure>` specification names this exact case in its opening line: *"an audio only version of a video podcast to allow apps to switch back and forth between audio/video."*

The vendor already emits three correctly-attributed `podcast:transcript` renditions per episode, so this is the same namespace and the same discipline they have demonstrably implemented.

```xml
<!-- UNCHANGED: audio stays the primary enclosure for legacy client compatibility -->
<enclosure url=".../uams118.mp3" length="14626798" type="audio/mpeg"/>

<!-- ASK 1 -->
<podcast:alternateEnclosure type="video/mp4" length="869044773" height="1080"
                            title="Vodcast" rel="video">
  <podcast:source uri="https://clientfiles.doctorpodcasting.com/arkansas_medical_sciences/uams118_vodcast.mp4"/>
  <podcast:source uri="https://www.youtube.com/watch?v=…"/>
</podcast:alternateEnclosure>

<!-- ASK 2 -->
<podcast:person role="host">Amanda Wilde</podcast:person>
<podcast:person role="guest" href="https://uamshealth.com/provider/gresham-t-richter/">Gresham Richter, M.D.</podcast:person>

<!-- ASK 3 -->
<podcast:episode display="118">118</podcast:episode>
```

**Ask 1 — `alternateEnclosure`.** Set `rel="video"`; an unset or `"default"` `rel` asserts the media is a different *encoding* of the same content, which is false for a different cut. Do **not** set `default="true"`, which specifically means "identical to the enclosure file." A `bitrate` attribute helps constrained clients choose.

**Ask 2 — `podcast:person`.** Delivers credits as structured data instead of scraped HTML, and `href` carries the provider URL that joins an episode to a `people` entry. **Item-level people wholly replace channel-level people** per the specification, so every item must restate the host or the host disappears for that episode.

**Ask 3 — `podcast:episode`.** Removes the dependence on parsing the enclosure filename and fixes the one item where that parse yields nothing.

**Explicitly do not change:** leave `<podcast:medium>` absent (it correctly defaults to `podcast`; `video` would misrepresent a catalog of 114 audio episodes with 10 video companions), and do not add `<podcast:season>`.

**Open items to resolve with the vendor:**

1. **Caption timeline.** `podcast:transcript` is item-scoped — its only attributes are `url`, `type`, `language`, `rel`, with no mechanism binding a transcript to a specific enclosure, and `alternateEnclosure` accepts only `podcast:source` and `podcast:integrity` children. A video-timed caption file therefore cannot be expressed. The clean fix is production-side: publish both renditions on a **shared timeline** so one caption file serves both. A `language`-tag hack such as `en-US-x-video` is not acceptable — apps would render it as a foreign-language track.
2. **Video duration has no home.** `alternateEnclosure` carries no duration attribute, and the edits differ. Ask how they intend to convey it.
3. **Is a web-delivery encode available?** If `podcast:source` is to point anywhere other than YouTube, it needs a real streaming rendition.

## Why this is not a `wordpress-importer` concern

The importer is a WXR tool. Its input is a WordPress export, and the podcast episodes have never been in one. Two further facts settle it:

- The chosen posture is **ongoing reconciliation**, not a one-shot load — a monthly episode plus a scheduled feed re-read is app-side service behavior, not a migration step.
- The source is an RSS feed and a set of HTML pages on a vendor host, sharing no code path with WXR parsing.

`UAMS-Web/wordpress-importer#424` is therefore superseded rather than blocked, and `#500` resolves as "source identified, not ours to import." `#443` is unaffected — it handles `audio_series` subtype tagging for audio that genuinely is WordPress content, such as the `heres-to-your-health` radio show.
