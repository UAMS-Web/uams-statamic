# Agent instructions: repository rules

These sections were moved out of [`AGENTS.md`](../AGENTS.md) to keep that file under the 32,768 bytes Codex reads by default (UAMS-Web/uams-statamic-archive#2840). `AGENTS.md` keeps a one-line summary of each and links here. Each section is a standing instruction for this repository; read the one that bears on a task before starting it.

## Running `boost:update`

Run `php artisan boost:update` **only as `boost:update --ignore-skills`**, as its own reviewed change, and **never as a refresh reached for mid-ticket**, per [`.claude/rules/running-boost-update.md`](../.claude/rules/running-boost-update.md). The one documented flag skips every skill write while the `AGENTS.md` guideline update keeps flowing (Boost no longer writes `CLAUDE.md`, UAMS-Web/uams-statamic-archive#2539); `boost.skills.exclude` is not a substitute (undocumented, and its `reject()` runs before Boost merges in custom skills, so it cannot suppress them). The decision and its rejected alternatives are in [`docs/DECISIONS.md`](DECISIONS.md) (UAMS-Web/uams-statamic-archive#2319).

## Supported development platforms

**macOS and Windows are both supported development platforms, and both stay in use.** Nothing in the rules, skills, or docs corpus may assume either is the only one, so a platform-conditional branch is never dead documentation to be deleted — each one is live guidance that has to be correct on the platform it names.

Two obligations follow, and they are the whole rule. **Name the platform a branch was verified on.** **And write paths repo-relative**, never as one machine's absolute path — `scripts/worktree-slots.mjs`, not `/Users/<user>/Herd/uams-statamic/scripts/worktree-slots.mjs`. An absolute path from the original checkout resolves on exactly one machine: it is wrong on a second Mac just as surely as it is on Windows, so a second machine's absolute path is not the fix.

## Rector on changed paths

After changing PHP under `app/`, run `vendor/bin/rector --dry-run` scoped to the files you changed, alongside the `vendor/bin/pint --dirty --format agent` the Pint rule already requires — Pint stays the formatter of record and the sole owner of unused-import removal. **Pass only paths under `app/`** — and this is **specific to Rector, not a rule about static analysis generally**; `phpstan` analyzes `tests/` at the same level as `app/`, so the two diverge on exactly a `tests/`-only diff. A path argument on the command line *overrides* [`rector.php`](../rector.php)'s `withPaths()`, so naming a `tests/`, `config/`, or `routes/` file applies an `app/`-tuned rule set to a surface the config deliberately excludes. Scoped it costs about two seconds against roughly two minutes repo-wide, which is what makes it a per-change habit rather than an occasional sweep.

The **gating profile** — [`rector.php`](../rector.php)'s default, and what `composer test:refactor` reports — is enforced by the `rector` job in [`.github/workflows/ci.yml`](../.github/workflows/ci.yml), which runs after `pint` and before `phpstan`. Pint must come first: both tools rewrite the same files, and `rector.php` sets `removeUnusedImports: false` so Pint stays the sole owner of that operation. `app/` is currently **clean** under that profile, so a finding your change introduces is yours, and it reds the job — fix it rather than leaving it.

A separate **sweep-only** set is held out of the gating profile by `rector.php`: `ReadOnlyClassRector`, `ReadOnlyPropertyRector`, `LocallyCalledStaticMethodToNonStaticRector`, `RemoveUselessVarTagRector`, and `RemoveDuplicatedReturnSelfDocblockRector`. Each makes a judgment call rather than a mechanical one — a semantic `readonly` promotion, a static demotion Rector cannot see the `tests/` callers of, a docblock the PHPDoc convention wants kept — so they stay unenforced and carry a standing backlog on files nobody has touched. Preview with `composer test:refactor:sweep`, apply with `composer refactor:sweep`, and review the diff: apply what is right for the change and leave the rest.

One trap the CI job encodes and a local run must too: Rector's file cache does **not** key on the active rule set, so a warm cache written under one profile makes a later run under the other silently under-report — a false green on a backlog it never re-analyzed. Give each run a private temp dir (`TMPDIR`/`TMP`/`TEMP`) rather than reaching for `--clear-cache`, which races a concurrent Rector.

## Closing a ticket

Work is finished when it is **legible**, not when it builds: per [`.claude/rules/closing-a-ticket.md`](../.claude/rules/closing-a-ticket.md), **never push to `main`** (branch and open a PR, even for a one-line docs fix), tick acceptance criteria as they are met and **name** any that will not be, move the board card in step with the branch, and give residue a ticket rather than a mention in a PR body. None of these break a build, which is why they need a rule. It composes with [`worktrees`](../.claude/rules/worktrees.md) (where you branch), [`local-ci`](../.claude/skills/local-ci/SKILL.md) (the gate), and [`writing-issues`](../.claude/skills/writing-issues/SKILL.md) (the board's transition table and field ids).

## Local CI runner

This repository **keeps** its own [`scripts/local-ci.mjs`](../scripts/local-ci.mjs), and it no longer gates a merge: `main` requires the remote `CI`, `Attribution footer` and `Closing keywords` checks, and a ready pull request merges when all three are green and every test-plan item is satisfied (#337). Do **not** adopt the shared runner from `UAMS-Web/uams-claude-skills` (`local-ci.json` + `.claude/skills/local-ci/local-ci.mjs`) here. The sync manifest excludes the shared `local-ci` skill for that reason. Capabilities this runner needs that the shared one does not ship: worktree-slot checkout, runner handoff, single-flight lock, private submodule init, parallel Pest with a serial tail, the mutation-tooling smoke, optional `--commit-status`, and the Mode A watcher / merge pipeline. Recorded on [#2835](https://github.com/UAMS-Web/uams-statamic-archive/issues/2835) for [`UAMS-Web/uams-claude-skills#11`](https://github.com/UAMS-Web/uams-claude-skills/issues/11).

## Pre-merge check

A green chain is not a merge decision. Before merging any pull request, work the check in [`.claude/rules/pre-merge-check.md`](../.claude/rules/pre-merge-check.md): reading the remote checks is one step of it, not the whole of it. It composes with [`local-ci`](../.claude/skills/local-ci/SKILL.md) (which owns the merge procedure in Mode A, reading those checks, and the verdict comment), [`sync-pr-branch`](../.claude/rules/sync-pr-branch.md) (bringing the branch current), [`closing-a-ticket`](../.claude/rules/closing-a-ticket.md) (what outlives a green build), and [`adversarial-review`](../.claude/rules/adversarial-review.md) (which the merge-time pass narrows rather than repeats).

## WordPress source corpora

Importer, blueprint, and migration claims are grounded in two corpora that live outside this repository — a local **`uamshealthmu`** WordPress install (plugin and theme *source*) and **[`UAMS-Web/wordpress-importer-exports`](https://github.com/UAMS-Web/wordpress-importer-exports)** (the exported production *content*). ## Adversarial review

Before shipping any non-trivial change, run an adversarial review per [`.claude/rules/adversarial-review.md`](../.claude/rules/adversarial-review.md): an independent, skeptical pass to *break* the change, then fix the real defects and re-run the gate. **In that order** — the review rewrites the diff, so a long validation started before it lands is evidence for code that no longer ships; and review agents must not run tests in the tree a validation is using. Mutation-verify fixed bugs and audit test rigor with Pest's `--mutate` (`composer mutate -- --class="App\<Class>"`; from a worktree scope to a relative sub-path — see the rule).

## Worktree slots

Branch work happens in one of a fixed set of long-lived, **pre-bootstrapped worktree slots** — never in a worktree created for a ticket and thrown away after — per [`.claude/rules/worktrees.md`](../.claude/rules/worktrees.md). The primary checkout holds `main`, serves the site, and is not a work surface; the slots (`../uams-statamic-a`, `../uams-statamic-b`) rest detached at `origin/main` and are claimed one at a time; `../uams-statamic-ci` belongs to the [`local-ci`](../.claude/skills/local-ci/SKILL.md) runner and is never hand-driven. **Refresh a slot before trusting any check run in it** whenever its base has moved — this is the one risk the model adds, and it is silent: a stale slot passes its tests against the wrong dependency versions, where a fresh worktree failed loudly on a missing `vendor/`. **Releasing a slot is the author's last act on a ticket**, because git allows a branch in one worktree only — a slot still holding `<N>-<slug>` blocks the validating run from checking that branch out at all. **On a fresh clone the slots do not exist yet** — `node scripts/worktree-slots.mjs provision a` (and `b`) stands each one up, once, and the rule covers what that does and why each step is there. It is roughly half a minute per slot on macOS; budget longer on Windows, where `public/assets` clones over the network.

## Sync PR branches before the gating run

Bring every PR branch current with `origin/main` before its gating validation and before opening the PR, per [`.claude/rules/sync-pr-branch.md`](../.claude/rules/sync-pr-branch.md), so a branch behind an *interacting* merge is never validated (or merged) against stale code. Genuinely file-disjoint branches are exempt.

## Impersonal voice in GitHub artifacts

Every PR body, issue body, and PR/issue comment posts under **one account**, so write them with no narrator in them per [`.claude/rules/impersonal-voice-in-github-artifacts.md`](../.claude/rules/impersonal-voice-in-github-artifacts.md): no `I`/`my`/`you`/`your`, and — the harder half — no vouching stance, since "all three defects are confirmed from use" carries no pronoun and still reads as the author confirming their own PR. Impersonal is not vague: keep every number, path, command, and ticket reference. Repo prose (`.claude/**`, `docs/**`, `README.md`) deliberately addresses a reader as "you", and verbatim quotations keep their original wording — both are carve-outs a sweep must not strip.

## American English, and the dictionary that overrides it

First-party prose is **American English**, arbitrated by **Merriam-Webster's first-listed spelling**, and [`cspell.json`](../cspell.json)'s `"language": "en"` already enforces it wherever the whole-tree `spell` job reaches. What is unguarded is the one way to defeat it: an entry in [`project-words.txt`](../project-words.txt) silences a word **repo-wide, permanently, and silently**. Per [`.claude/rules/american-english-prose.md`](../.claude/rules/american-english-prose.md), such an entry needs a stated reason, and only two qualify — a name that cannot be reworded (`phpstan analyse`, a place name), or generated/verbatim external data, where a **path exclusion is preferred** because it is scoped and visible where a dictionary entry is global and invisible. The British spelling of `defense` is the worked example: removing the entry yields exactly one gate hit, from a script, and none from the standardized data it was defended as protecting — so it guarded nothing while silencing the word everywhere. Note *why* the data is safe, because two mechanisms are at work and only one is a policy: nine occurrences under `app/Enums/` are covered by `cspell.json`'s `ignorePaths`, while three under `app/Services/EnumGeneration/Schema/` are simply in extensions cspell never scans. (It is named by reference rather than spelled out, here and in the rule, because writing it adds a fresh gate hit the moment the entry is removed — the rule applying to its own documentation.) **The reason cannot be written beside the word** — a comment below the file's header is a stray that [`scripts/project-words-sorted.test.mjs`](../scripts/project-words-sorted.test.mjs) fails on (UAMS-Web/uams-statamic-archive#1922) — so it goes in the PR that adds the entry, retrievable with `git log -S'<word>' -- project-words.txt`. The established reasons for this repository's entries are recorded in [`docs/spelling-dictionary-entries.md`](spelling-dictionary-entries.md).

## Decision log

**[`docs/DECISIONS.md`](DECISIONS.md)** is the canonical decision log: the *why* + **rejected alternatives** behind the specs. **Consult it before acting** — before proposing a change, reopening a question, or picking an approach, check whether it's already a decided-and-recorded path (or a rejected one). It is the guard against silently relitigating a settled decision. **When a seam closes**, record the verdict in **both places** — the *what* + *why* + rejected alternatives in [`docs/DECISIONS.md`](DECISIONS.md) (the canonical cross-ticket log) **and** in the GitHub issue's `## Decision` section (the per-ticket record, still the system of record for a single ticket's status) — with the full reasoning in the relevant [`docs/`](.) companion when the decision touches a documented area. Keep the two in sync. Composes with the [`design-decision-forks`](../.claude/rules/design-decision-forks.md) rule, which governs how a fork is surfaced and resolved *before* its verdict lands here.

## Measurement parity

Before comparing any timing against a prior baseline, **read the harness that produced that baseline and reproduce its whole job**, per [`.claude/rules/measurement-parity.md`](../.claude/rules/measurement-parity.md) — not just its headline command. For this repo's suite bands the most-missed step is `php artisan route:cache` up front; omitting it roughly doubles the band and silently inverts the conclusion. Log each parity step's exit code, state the parity basis alongside the number, and confirm the workload was identical by matching **assertion counts**, not just durations. Know which flags observe the workload versus change it: `pest --update-shards` runs functionally (one process per test, ~4× CPU) and its wall time is never a band time.

## Cutting releases

Cut a release each business day at 10:00 Central when `main` carries unreleased work, per [`.claude/rules/cutting-releases.md`](../.claude/rules/cutting-releases.md). A breaking change ships at the next daily cut, and its notes lead with a breaking-change callout. Releases are retrospective `--prerelease` tags on `main` (a changelog checkpoint, not a deploy gate): the *when* is that rule, the *how* (title, notes, `gen_release_notes.py`, `gh`) is the [`writing-release-notes`](../.claude/skills/writing-release-notes/SKILL.md) skill, and the 0.x versioning rationale is in [`docs/DECISIONS.md`](DECISIONS.md).

## Filing defects across repositories

A defect in a dependency or a sibling `UAMS-Web` repository gets **an issue in that repository** — not a pull-request aside, not a coordination message, and not a comment on an issue that is already closed, which is the one place guaranteed never to be revisited. And when several sessions could plausibly find the same thing at once — they coordinate with each other, adopt the same release, and run the same diagnostics — **announce the work and claim it before filing**, per [`.claude/rules/filing-defects-across-repos.md`](../.claude/rules/filing-defects-across-repos.md). A claim orders claimants rather than excluding them, so it is not a lock; and it prevents duplicate *filings* but not two distinct issues that edit the same lines, which is why overlaps get cross-linked in the issue bodies rather than only on the wire. It composes with [`closing-a-ticket`](../.claude/rules/closing-a-ticket.md) (the same instinct, for residue from a ticket here) and with the [`writing-issues`](../.claude/skills/writing-issues/SKILL.md) skill, which owns how the body is written.

## Claude Code cloud sessions

In a Claude Code cloud session, read [`docs/runbooks/claude-code-cloud-sessions.md`](runbooks/claude-code-cloud-sessions.md) **before** attempting a bootstrap. Cloud sessions are scoped to **issue and docs work**; app work stays on a local checkout, where [`local-ci`](../.claude/skills/local-ci/SKILL.md) remains the gate. **Never run `composer install --prefer-dist` there**: every dist URL is an `api.github.com` zipball whose 403 presents as a *hang* under CONNECT rather than a fast failure, so it burns roughly fifteen minutes and produces nothing. Private repos additionally need a per-session `add_repo` call that no setup script or `SessionStart` hook can pre-bake, because both run before the tool is callable. The verdict and its rejected alternatives are recorded in [`docs/DECISIONS.md`](DECISIONS.md).
